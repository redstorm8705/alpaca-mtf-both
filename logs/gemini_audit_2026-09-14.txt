### MODIFIED FILE FINDINGS

#### 1. `execution/orphan_manager.py`
- **Function**: `cancel_and_reconcile_gtc_stops`
- **Variable**: `fill_price`
- **Code Path & Trace**:
  ```python
  fill_price = float(
      order.filled_avg_price or trade.get("entry_price", 0)
  )
  ```
  When Alpaca's order object has `filled_avg_price=None` (transiently during execution settlement), fallback defaults to `trade.get("entry_price", 0)`.
  Then:
  ```python
  pnl = tracker.record_gtc_triggered(symbol, fill_price)
  ```
  `record_gtc_triggered` calculates $PnL = (exit\_price - entry\_price) \times qty$. If `fill_price` falls back to `entry_price`, $PnL$ evaluates exactly to $0.00$. This explains why `trade_events` initially logged `EWY` stop_hit with `price: 189.63` and `pnl: 0.0` despite the stop being hit at $179.78.
- **Failure Condition**: Any GTC stop filled overnight where Alpaca does not supply `filled_avg_price` immediately on first query records a fake $0.00 P&L trade in the event stream until asynchronous reconciliation catches it.

#### 2. `scripts/audit_slack.py`
- **Function**: `findings_from_report`
- **Variables**: `_CONT_FIELD`, `_ITEM_MARKER`, `new_item`
- **Code Path & Trace**:
  The parser groups continuation lines into finding blocks based on regex:
  ```python
  new_item = bool(_ITEM_MARKER.match(raw)) or (
      bool(_BOLD_LEAD.match(line)) and not _CONT_FIELD.match(line))
  ```
  If a model emits findings using Markdown lists with sub-bullets that start with bold text not in `_CONT_FIELD` (e.g. `* **Context**: ...` or `* **Root Cause**: ...`), `_ITEM_MARKER` evaluates to `True` because of the leading list marker `* `, bypassing `and not _CONT_FIELD.match(line)` and splitting sub-bullets into separate findings.
- **Failure Condition**: Any report containing bulleted continuation items like `* **Detail**: foo` splits into multiple fragmented findings on the Slack card.
