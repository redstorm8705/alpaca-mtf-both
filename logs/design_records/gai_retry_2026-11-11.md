## Problem (measured)
- 11-10: GAI looked "down" for hours. The real cause was bursty free-tier 429s, but `_curl` cut every provider error to
  200 characters of `str(dict)`, and the stand-in line printed only 60. Google's QuotaFailure (which quota) and
  RetryInfo.retryDelay (how long to wait) never reached the log. The one retry waited a fixed 6 s whatever Google asked.

## Change
1. `_curl`: a provider error reply raises `ProviderError` (a RuntimeError subclass, so every existing handler still
   catches it) carrying a summary in this order: code, status, each exhausted quota id and limit, retryDelay, then
   the message (240 chars) last, so a cut drops the generic message before the quota or the wait. `retry_after` =
   Google's soonest retryDelay in seconds; `per_day` = every listed quota is a daily one. Every piece is scrubbed
   before any cut; 600 chars.
2. `_gai`: the ladder error names every model's reason (600 chars each, 4000 total). The retry and paid-key decisions
   still classify ONLY the text origin/main raised for the last model (`last_reason` = the old scrubbed 200-char error text), so they are identical to main, so no new retry or paid path
   opens. When that reason is transient, the one retry waits the soonest retryDelay any model gave, plus 1 s (6 s when
   none was given); no wait and no retry when every model reported a daily quota, or when the asked wait exceeds one
   per-minute quota window plus 5 s (65 s). The caller's fallback then runs at once.
3. The "GAI down" stand-in line prints the full reason instead of 60 characters.

## Dropped after measurement: scaling the NVIDIA pair timeout with diff size
Measured 11-11 (real preship_audit.py diff cut to 8.5K / 25K / 50K / 67K characters, 2 runs each): every Mistral call
ended at 340 s against a 1200 s client limit, at every size including 8.5K (the one reply text captured, at 8K, was an
empty body from integrate.api.nvidia.com; at 25K-67K the error text was not recorded); the bake-off prompts (1.0-1.6K)
finished in 20-277 s. The cut is on NVIDIA's side at about 340 s, so a longer client time limit cannot help. MiniMax
spent all 6000 tokens on reasoning (5999 reasoning tokens) with no verdict in 5 of 8 runs (8.5K x2, 25K x1, 67K x2), in
209-257 s; the other 3 (25K x1, 50K x2) errored at 0 s, cause not captured. Not tested on 11-11: a small-prompt
control, so an NVIDIA endpoint problem that day is not ruled out (the 11-09 bake-off at 1.0-1.6K worked). Raw output:
scratchpad bake/nv_size_*.json and bake/nv_one_out_8k.txt. Diff size breaks the pair through output length and a server cap, not our timeout. Follow-up to
test: review a large diff in file/hunk pieces sized to what the bake-off proved (<= ~1.6K characters), measured against
the bake-off cases before any build.
