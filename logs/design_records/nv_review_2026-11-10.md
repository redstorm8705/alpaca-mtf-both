## Problem (measured)
- 11-09/10: Codex at its usage limit until 11-14; the Gro fallback (Groq, 8k tokens per request) chunked large diffs and
  rejected 13 times across QHM-COVER, QHM-REENTRY and DAY-VETO, every claim refuted at source (it cannot see across
  chunks). Fixes stalled for hours; the owner waived Gro three times.
- Bake-off (BAKEOFF-1025 cases: 4 planted bugs, 6 clean, x2): Mistral Large 4 7/8 bugs, 0/12 false rejects; MiniMax M3.1
  6/8, 0/12; today's NVIDIA substitute llama-3.2-90b 2/4 bugs, 3/6 false rejects. Both strong models often returned
  empty content (no verdict 7/20 and 9/20).
- 11-09: a TimeoutExpired message printed the NVIDIA key (it is on curl's argv). Gemini's key is in the URL (?key=), so
  the same path can print it.

## Change
1. Reviewer #2 when Codex is unavailable = the NVIDIA pair (Mistral Large 4, MiniMax M3.1), for every diff. Gro is a last
   resort only when the NVIDIA endpoint is down AND the diff fits Gro's per-request limit; an oversized diff with NVIDIA
   down fails closed (no chunked review).
2. The GAI slot, when Gemini is unavailable, also uses the pair (replacing the llama ladder).
3. Pair rule: both models are asked in parallel with the same prompt. A REJECT from either -> REJECT. APPROVE needs at
   least one APPROVE and no REJECT; the marker records whether it was 2-of-2 or 1-of-2. A model with no verdict is
   retried once; both unusable -> fail closed (no marker).
4. Verdict text: read only the model's final `content`. Empty content is "no verdict" (never parsed from reasoning text).
   max_tokens and the per-model timeout are derived from the bake-off's observed latency and output length (p90 of the
   successful runs), not fixed guesses; total time is bounded by running the two models in parallel.
5. No reviewer shopping (closes a gap both board seats found at source): today only a Codex REJECT blocks the fallback.
   New rule: an open REJECT from ANY reviewer (Codex, either pair model, Gro, or GAI) on a file's current content blocks
   every fallback for that file until that reviewer approves later content or the author answers it with --evidence and
   the same reviewer clears it. GAI verdicts are logged to the verdict log too.
6. Key safety, all three providers, inside the shared `_curl`: headers (incl. the API key) go to curl through a header
   file (`-H @file`), unique per process, mode 600, written and deleted inside the same try/finally; Gemini's key moves
   from the URL to an `x-goog-api-key` header. `_redact()` (masks every .env value) is applied to every error string and
   every verdict-log reason.
7. Audit trail: the marker records both model ids and both verdicts (`reviewer_b_models`), the label says "nvidia-pair",
   and the per-run model id is not a module global.
8. Precondition: the pair stands in only when the file's cold-2nd PASS is recorded and fresh for the exact staged
   content (owner direction); otherwise fail closed.

## Tests (new .claude/preship/test_nv_review_1110.py, no network)
- every combination of {APPROVE, REJECT, empty, timeout, 404} for the two models -> the combined verdict; both unusable
  -> fail closed; 1-of-2 recorded;
- an empty `content` with an APPROVE in reasoning text -> no verdict;
- a seeded REJECT from each reviewer blocks every fallback on the same content; cleared only as described;
- after a forced TimeoutExpired, no key value appears in any returned or logged text (all three providers);
- cold-2nd missing or stale -> the pair does not stand in.
Acceptance (before merge, network, recorded): re-run the bake-off through the new code path; pass if the pair catches
>= 7/8, false-rejects <= 1/12, and gives no verdict on at most a quarter of clean cases.

## Reversal
If the pair misses a bug a later reviewer finds, or its no-verdict rate blocks more than a quarter of clean files in its
first ten real uses, revert to the prior ladder and report to the owner.
