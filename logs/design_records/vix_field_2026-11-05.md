## 1. Problem (code-traced; how often it happened live is unmeasured — server logs not readable from this session)
`RegimeDetector._refresh` (`strategy/volatility_regime.py:109-142`) stores the VIX level (`:119`) or, when the Yahoo
VIX fetch fails, SPY's 10-day realized volatility (`:128`) in the same `_realized_vol` field, and `_build_result`
returns it as `"realized_vol"`. Every reader treats that number as VIX:

| Reader | Where | VIX rule it feeds |
|---|---|---|
| `_main._last_vix` | `strategy/run_cycle.py:1080`, `:1156` | core-tier min-score gates: VIX > 30 → +3, > 25 → +2, < 14 → +2 (`:1671-1676`) |
| `check_partial_exits(last_vix=…)` | `execution/exit_logic.py:874` | "stressed" T2 partial when VIX > 30 |
| `get_be_buffer_mult(symbol, last_vix)` | `execution/exit_logic.py:1465`, `execution/param_engine.py:174` | break-even buffer widens at VIX ≥ 20 / ≥ 30 |
| stop-breach confirmation | `execution/exit_logic.py:1776` | 1 bar instead of 3 when VIX ≥ `VIX_STOP_WIDEN_THRESHOLD_2` (30) |
| BoD-4 overnight zero | `strategy/run_cycle.py:1808-1814` | no new sizing against overnight risk when VIX > 35 |
| regime label | `strategy/volatility_regime.py:132-137` | LOW < 12 / HIGH > 25 (label + inert size multiplier) |

Example of the mechanism (illustrative numbers, not a logged day): the Yahoo fetch fails on a calm day when VIX is 17
and SPY 10-day realized vol is 11. The bot reads "VIX 11": the < 14 gate raises the core minimum score from 8 to 10, so
fewer entries clear. On a stressed day with VIX 36 and SPY realized vol 28, the VIX > 30 / > 35 protections stay off:
stops wait 3 bars instead of 1, the stressed T2 partial does not apply, and BoD-4 does not block new overnight sizing.
[hypothesis — unverified: realized vol usually sits below VIX, so outage days loosen the stress rules and tighten the
calm-market gate.]

If both fetches fail, `_refresh` returns early (`:125-127`) and the last value is reused with no age limit.

## 2. Proposed fix
1. **Separate the two series.** `get_regime()` returns `vix` (float or None), `vix_asof` (timestamp of the reading),
   `spy_rvol_10d` (float or None) and `vol_source` (`vix` / `vix_equivalent` / `none`). `realized_vol` stays for the
   existing readers that want realized vol (`regime_state.py`, `tier_capital_allocator.py:1102`, the trade log) and is
   always SPY realized vol, never VIX.
2. **One accessor for every VIX rule:** `vix_for_rules()` returns, in order:
   - the fresh VIX reading;
   - else a **VIX-equivalent derived from SPY realized vol**: today's SPY 10-day RV × the trailing median of
     (VIX close ÷ SPY 10-day RV), computed once a day from a year of VIX daily closes (T4, the same Yahoo source) and
     SPY daily bars (T1 Alpaca). Data-derived, so no new fixed number;
   - else None.
   Every row in the table above reads this accessor instead of `realized_vol`.
3. **When it is None:** entry gates use the base minimum score (no VIX layer); exit rules use their normal-market
   setting; BoD-4 does not fire. One Slack alert per day plus a log line. That is today's behaviour on a cold start
   (`_last_vix == 0` skips the gates); it is now explicit.
4. **Log every refresh:** `VOL vix=… asof=… spy_rvol10=… equiv=… source=… regime=…`.
5. **No threshold changes.** The 12 / 14 / 20 / 25 / 30 / 35 cut-offs stay as they are (grandfathered); replacing them
   with percentiles is the separate REGIME-SIZE / regime phase-2 item. No new numeric literals except the estimator
   window for the median, which comes from the data history length.

## 3. Risk path and approval
Changes entry frequency (score gates) and exit behaviour on outage days → risk-path: board with the masked-loss seat,
GAI + Codex, owner approval before code. It narrows the envelope's blind spot (protections that silently switch off);
it does not widen it.

## 4. Replay before shipping (front-loaded)
- Server logs: every "Volatility regime: … (SPY realized vol (VIX fallback): x)" line since the log starts → list of
  fallback cycles and days.
- For each: the actual VIX close that day (Yahoo history), the SPY RV used, the VIX-equivalent the new rule would
  produce, and which rules (score gate, stop confirmation, T2, BE buffer, BoD-4) differ between old and new.
- Then the trades on those days: entries skipped or taken, exits whose timing would change, using Alpaca fills.
- Wrong if: fallback days are rare enough that no rule ever differed (then the fix is hygiene only), or the
  VIX-equivalent misses the real VIX close by more than the gap between adjacent cut-offs on most fallback days.

## 5. Tests
VIX present / VIX missing with RV present / both missing / stale VIX; each reader gets the expected value; the old
`realized_vol` key never carries VIX.
